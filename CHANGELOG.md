# Changelog

## 0.3.3 - Unreleased

### Fixed
- The refresh hook reads a READY only inside a session message's own body, never in text after it closes; and it now sees the usual wordings: READY anywhere in the first line (not "not READY"), a READY line after a bullet, and "Re-sign please" (#C265, Checker).
- A stale "as of" stamp says "· old" in the warning colour at full contrast; dimmed to half, it read at about 2:1 (#C265, Designer).

## 0.3.2 - 2026-10-26

### Fixed
- The gate lays its journal over each collection from when that collection was listed, not from the export's newest file, so an ask and thread written while an export ran are seen (#C264: the lead's messages into c226-iphone-test were refused).

### Added
- Phase times from the evidence (#C235): the collector works out when each phase ran from the repository, not from steps someone remembered to log: plan from the card to its branch's first commit, build to READY (never after the first sign-off), each review to its sign-off note's time (in the order the notes came; the one the card waits on runs open), ship from the ship run taking the work to the first deploy run on main that has it, live that run. Open cards and those closed in the last 7 days, in `derived/all` as `times`; one deploy-run list per run. On the page each phase the evidence shows replaces the steps' times for it (who and waits kept); steps fill only phases with no evidence (a test, a design talk, a one-commit branch's plan and build). A finished phase with neither says "no record" in grey.
- The repository's reading says how old it is (#C237): "as of 12 min ago" beside a card's repository mark, greyed past 30 minutes. A READY another session sends the lead asks for a collector run at the end of its turn (the refresh hook).

### Changed
- A card's phase comes from its branch's current tip (#C237): an older commit of the branch that a release named counts only once the branch is gone, so a card whose first try shipped and whose rework waits no longer shows "Live in" the old version. One card is one branch: a card with two takes the least advanced one's phase, names it on the card, and the collector prints a `CONFLICT` to split the rework into a sub-card; the gate refuses a card write that lists branches or names another branch than the card's. Main and a ship run's candidate branch are never a card's branch.
- Who an item waits on comes from one function, `waitsOn`, for its section and its badge alike (#C236): an answered ask under "Waiting on Manager" says so (it said "waiting on you"). A page lint keeps every badge in `badge()`.
- Every live re-draw keeps each fold as the owner left it, wherever its thread lands, and the scroll position (#C241); Needs you's thread rows are no longer drawn shut.

## 0.3.1 - Unreleased

### Fixed
- An ask's own text sits on its own line under the #T number, title and badge, with a small gap (#C234: it ran on after "waiting on you").
- The gate lays threads written since the collector's export over its mirror, so a thread the lead just numbered is no longer refused as unnumbered (#C234; it came with #C227's thread export). Only onto a mirror that has threads.
- `scripts/current.mjs` makes the install root before its check copy, and a dry run copies nothing (Checker).

### Added
- The current link (#C223): the scheduled collector runs from `~/.flight-board/current`, a symlink to a pinned signed commit, which `scripts/current.mjs` moves only to a commit on main with Security's `SECURE` note, and only to a copy that is exactly that commit. A collector, page or task change no longer needs the owner's install; the gate, the refresh hook, the fence and what they import stay pinned in the settings and do. The fence accepts the link only while it points at a pinned copy, and a run's step 2 refuses code other than step 1's. Security's review is what gates a link move (the README says so).
- Unnumbered threads (#C227): the collector exports `threads` and prints a `NUDGE` line every run while a thread has no number, for the lead to number it.
- Choices need buttons (#C227): the gate refuses a waiting item whose text, question or title offers lettered or numbered choices (`A) … B)`, `1) … 2)`, "option A") unless it is a `decision` with options. An update that doesn't name the kind is checked against the mirror's.
- A review only some cards need: the skip kind `unlessTrue` skips a phase unless the card's field is `true` (a designer's review, on `lookChange: true`), on the page and in the collector. A card in a ship run is marked `shipping: true`, never with the branch's name (Security).
- The ship run is the source of truth (#C211): while a run's candidate branch exists (`collector.candidatePattern`), the cards it names show "Shipping now" and the other signed cards "Queued (n)"; after it, only those cards carry the version main names. The refresh hook starts the collector when a ship starts or ends. The live page read stops at 256 KB as it streams, and refuses a redirect off https (Checker, Security); the gate's archive refusals no longer repeat the path (Checker).
- Versions from the repository (#C211): a card shows the version it went out in (live or deploying), else its place in the shipping queue (signed cards by when they went READY: "Ships next", "2nd in queue"), "In review" or "Building". `plannedVersion` is retired: the gate refuses it on a card (removing it is fine) and the page no longer asks for it. "Live now" is the build the live site serves (`collector.liveUrl`, `collector.liveTag`), with "deploying" while main is ahead; without a live address, the lead's `meta/live` as before.
- Closed cards' steps are archived (`scripts/steps-archive.mjs`, the lead's tool): for each card done or dropped a day ago or more, `timings/<card id>` keeps its steps as they were, and they leave the `steps` collection, which every page load and collector run reads. The page counts a closed card's steps from both places, each once by its id, so a stop between batches or a step logged after the archive changes nothing; a rerun deletes only what is archived. An open card's timings never count. The gate lets only the lead write `timings` or delete a step (Security, Checker). Refusals name threads through `idText`.
- Cards show the repository's phase (derived/all) when the collector has firm evidence: a card on main and deployed says "Live, still open" (never stalled), a signed review moves it on with no step logged, and the agent on that phase is named. The steps still give the times; a step phase that disagrees shows as "steps say …" on the evidence chip. Steps win only when newer than the collector's run and further on (a review signed since). The stall clock counts from the READY commit too.
- Card numbers (`#C12`), like thread numbers: a new card takes `num` from `meta/cardSeq` in the same batch (pinned, no gaps, never back), and keeps it for good; `scripts/card-ids.mjs` numbers the open and recent cards that have none. The `C` keeps them from being read as threads' `#T12`.
- The owner's strip, step 5 of v3: in the new layout, what needs you and the "Start a thread" box stay at the top, whatever the tab (sticky, scrolling on its own when long). They are the same elements as on the current board, moved there and back, so a draft or an open answer goes with them.
- The Crew view, step 4 of v3 (a third tab): a tile per agent with its model and effort, its memory (with "/clear me" once saved, dimmed when the reading is old) and what it is on, each card with its phase, or its idle note; then the last 7 days' time by phase (working, queued while busy, gated). The memory, crew and time-spent code is shared with the current board's (no change there).
- The Now view's cards have their own reply boxes (ids `tnote-now-…`), so a reply sent from the current board after a visit to the new layout no longer reads the hidden copy and gets lost (Checker). A derived state or chip named like a built-in ("constructor") shows nothing, and the time and crew maps have no prototype (Security).
- The Now view, step 3 of v3, the new layout's first tab: the open cards grouped under the plan node they serve, in the plan's order (each group headed by its node, its state and the path above it), cards no node claims last; then, folded, what shipped and the threads resolved in the last 24 hours. Tabs switch between Now and Plan (this browser's choice). A thread link opens the copy on screen, else the current board's.
- The Plan view, step 2 of v3: "Try the new layout" (or `#v3` in the link) shows the plan as an outline, each node with its state (done, in progress, gated with what it waits on, next), each objective with its bar and an on track / at risk / blocked chip against its due day, replaced nodes struck through with when, why, their replacement and the decision's thread, the cards on each node, and the open ideas at the bottom. The current board stays the default; the choice is this browser's only. The collector works the states out (`collector/plan-state.mjs`) and writes them into `derived/all` as `plan`.
- The plan layer, step 1 of v3 (data and gate only; the page doesn't show it yet): a `plan` collection of nodes (`objective`, `milestone`, `step`, nested by `parent`, with `outcome`, `measure`, `due`, `waitsOn`, a declared `state` with `evidence`). Only the lead writes it; a node is never deleted, and one that has cards is replaced (`replacedBy`, `changedAt`, `why`), never edited in its `text` or `outcome`. Every new card names the plan node it serves (`plan`), a real node that wasn't replaced. The collector exports `plan` too (optional: a board without a plan still exports complete).

### Changed
- Every thread shows its number (thread-num-always): the gate refuses a new waiting item, or a message that opens an unnumbered thread, unless the same batch sets `threads/<id>` `{num, title}` and moves `meta/threadSeq`; `scripts/thread-ids.mjs` now also numbers waiting items with none (opened at their `since`) and names every thread without a title. Every item and thread row reads "#T12 · title", every waiting row says "waiting on you" (red), threads say "waiting on Manager" (blue), "answered" or "resolved" (grey); amber is kept for a wait on another agent; every colour passes 4.5:1 on the panel in light and dark; a badge never breaks across lines.
- Open cards sort with the most advanced on top: by status (stuck, active, queued, paused) as before, then the furthest phase first in the config's order, then the sooner ETA (it was status, then ETA).
- One open phase per card, in the gate: a review can't start while build is open ("Build is still open by <who> since <time>: end it first"), ship can't while anything is; reviews may overlap, and build may start while a review waits (a fix round). The gate lays steps written since the last export over its mirror, so an end just written counts. The collector notes each READY card's `readyAt` (its READY commit's time), and the page ends a build step left open there, marked derived.
- A card's "Live in" is derived from its phase, no longer only the `etaLive` it was given when it was made (a card 4 minutes into a 10-minute ship showed 3 h 11 min): in ship, the release start plus about 10 minutes; before it, what is left of this phase plus the median of each phase still ahead (from the cards that went live), skips left out. The declared `etaLive` is the fallback where a phase has no history yet, marked "(declared)"; "ETA passed" follows the ETA shown.
- The collector also runs on demand: when the lead's turn ends after a ship, an item marked done or the owner's "refresh", a Stop hook (`collector/refresh.mjs`) tells it to start the collector task now. At most once per 10 minutes, never while a run is in flight. New config block `collector.refresh` (repos, taskId, debounceMin, flightMin).
- A thread shows its newest message first, under one reply box at the top. An ask you haven't answered keeps only its own box (its buttons and note), so the thread's box no longer shows a second time after the last message. Once you have answered, the thread's box takes its place.
- The collector's fence (`collector/fence.mjs`): a PreToolUse hook on every tool, in the collector's state folder only, that lets through exactly the steps of TASK.md (the two collect commands, the board's exports into the run's scratchpad, set `derived/all` from its file, one message to the lead) and refuses everything else, failing closed. It is what makes the collector safe to run in auto mode, where the board write no longer asks every hour (Security).
- Every ask, answer and initiative shows its thread's #T number (copy on click) and, once renamed, its name on its top line, before it opens. With no name of its own, a thread is named by its item's text, so none is ever unnamed.
- The gate's journal (laid over the mirror) and its known cards are written by `gate/after.mjs`, once the board applied a write: a write the gate let through but the app or a stale pin refused no longer shows as done (Security).
- A reply's or thread message's files: an image is a thumbnail that opens in the board's lightbox (← →, zoom, Esc), with that message's other images; any other file downloads in place. No new tab, which a sandboxed board can't open (the links were broken).
- The "Start a thread" box takes files like a reply box: Attach, paste or drop images and files; they go on the new thread's first message.
- Text boxes work like the chat app where a box has one action (a thread's Send, Send to Manager, an answer's Ack): Enter sends; Shift+Enter or ⌘+Enter (Ctrl+Enter off a Mac) adds a line. Where a box has two outcomes (Done or "Something went wrong", OK or "Change something", options), Enter does nothing and the box says to click a button. Nothing while an input method composes, in an empty box or on a disabled button.
- The collector runs hourly (the app's scheduler): the gate counts its mirror fresh for 75 minutes, not 30 (`gate.mirrorMaxAgeMin`), so the board-state rules keep running between runs. A scheduled run's session takes the task's own title, so the task is titled `Collector` and the role rule is unchanged.
- The collector's first run (TASK.md): the folder is set in the app's view of the task and checked after saving; the export's folder (`mirror.next`) and step 3's `out` are the task's `additionalDirectories`, never their parent; the lead is messaged by session id, since a scheduled run reaches no session by name; a correct run asks for nothing, so any prompt is answered Deny and the run stopped (an "always allow" stays on the task).
- The collector's second run asked about ten times (TASK.md, Security): its commands run exactly as allowed (no `cd … &&`); it may read only step 3's `derived-all.json` (the export, mirror, gate state, config folder and `~/.claude` denied, no bare Read deny, which blocked the write from file); it messages the lead with `mcp__ccd_session_mgmt__send_message` by session id (SendMessage can't from a scheduled run), the tools that stop, clear, archive, delete or re-permission a session denied; ToolSearch and the plan tools allowed; `model: haiku`.
- The collector runs in the board's own state folder (`<gate.stateDir>/<board id>`), its settings file there, the code by the pinned install's full path: a scheduled run saves exports only inside its own folder (`additionalDirectories` didn't help; the second trial asked for every export). Step 3's version read saves to `<dir>/out`.
- The collector's export goes to the run's own scratchpad, the one place a scheduled run saves without asking (a throwaway task showed it, 2026-10-25): `--prepare` notes the time; step 2 takes only this run's export (made after it, all seven collections, a real folder under this folder's scratchpad root) by moving it into place, keeps only `<collection>/<doc>.json` files, and stops with an error when there is none. The run's scratchpad is denied to Read.
- `collector.outDir` (config): where the collector writes `derived-all.json`. The scheduled run sets it outside its own folder, so its settings deny Read on the whole state folder (it holds the mirror, the gate's state and a clone, and anything added later) and allow only that file; the shell's readers are denied too (Security).

### Added
- The Threads panel in order: Start a thread, Needs you, Waiting on Manager, Later, then Resolved threads (last 7 days, folded) with a search box that finds any resolved thread, whatever its age, by name, #T number, item text or any message.
- `gate/after.mjs`, a PostToolUse hook (installed with the others): after a board write the board applied, it records the thread counter, so the gate's "never back" follows what the board holds and a refused batch can be sent again. Both hooks write the gate's state whole (a file of its own, renamed into place).
- Thread numbers and names: each thread gets a number (#T27) in the order threads opened, shown with a copy button; the Threads panel shows its name in bold, and a renamed thread shows its name on top. `#T27` in any message links to that thread; a message naming one tells the lead which threads to read first. The owner renames a thread from the board; the lead numbers them (`scripts/thread-ids.mjs`, backfill included), the gate keeping both the lead's.
- A Close button on every open thread: the owner's message marks it resolved (and closes an ask or idea), with no ping; it folds into Resolved.
- A message may name the one it answers (`after: <message id>`); it then always comes after it, whatever the clocks said.

### Fixed
- Send takes the text out of the box at once: no kept draft after sending, no second send of the same text; a failed save puts it back.
- The gate lays every write it let through since the mirror's export over the mirror, so a card closed since shows closed and the board-state rules keep running (a card closed earlier showed as still on build).

## 0.2.0 - Unreleased

### Added
- The write gate (`gate/`): the board's rules on every write; decisions with two options or more, context and per-option screenshots for a look; commands as `{text, cmd}`; each role's own memory tile (the lead keeps the keeper's writes); passing agent states never become items; the stuck line after three refusals in a row, shown on the page and cleared by the item's next good write; hand-offs name an existing card; the Stop hook for verdicts and thread answers.
- `scripts/hooks.mjs`: the gate's settings entries, printed or written, every path single-quoted for sh (nothing in it expands); `--retire <text>` removes an older gate's hook in the same write; a one-line summary of the change and a timestamped backup. `--pin <signed commit>` (required) exports that commit with git archive to `~/.flight-board/install/<sha>` and points the hooks there, so they never run a checkout someone is editing; upgrading is installing a newer signed sha.
- The gate refuses an edit in place (str_replace) on the board, and lets only the lead set or delete the whole of meta/context or meta/stuck (Checker).
- `DECISIONS.md`: the role check is an integrity check, never access control; the gate fails open on its own errors.
- Not in the gate: a reused id (the board's server refuses a set without if_version); phase order, one item per role and phase, and done-only-when-closed come with the collector, which keeps the board's mirror.

## 0.1.0 - Unreleased

### Added
- The board page as a template, with everything particular to one team in its own `board.config.json`: title, owner, phases, roles, skips, usage labels.
- Threads: every item is a thread (`messages`); a "Start a thread" box (question or idea); a reply reopens a resolved ask or idea; each message from the owner pings the lead agent as `Board thread [<thread>]: <owner>: <text>`, or waits for its check with `meta/board.wake` "batch".
- A bare Ack on an answer closes it; a note on any button also goes in the item's thread, so a question in it waits for an answer.
- The content scan before every push, against the team's private word list and for artifact links, real emails and phone numbers, and tokens.
- `scripts/install.mjs`, `scripts/build-page.mjs`, and tests for every rule.

### Fixed (review, before 0.1.0)
- The pre-push scan reads what the push sends: every file each pushed commit adds or changes, and each commit's message, not the working tree. `--all` scans every commit ever made, for the check before going public.
- The scan also catches phone numbers written as digits (+13035550100 style), Stripe, webhook, Resend and fine-grained GitHub keys; it refuses a word list with no words; no-reply addresses pass.
- `install.mjs` keeps the config and word list outside the repository from any folder in it.
- The scan reads a merge's own changes, ranges a push against that remote only (a first push to a new remote scans everything), and scans pushed annotated tags (tagger and message, not the time) and every commit's author and committer.
