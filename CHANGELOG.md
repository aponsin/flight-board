## 0.3.4 - Unreleased

- The steps file's wording about the hooks line is held by a test (steps-text-hooks-line, #C938). The wording itself was already right since #C931 (the one command only reminds you of the hooks step and prints no line for it; the owner pastes line 3 from the pair's post); what was left was a test title that still said the command "prints line 3 to paste", and nothing that failed if the steps text said so again. `tests/make-pair-ran.test.mjs` now asserts the sentence on a pair that has a hooks line and that no steps text says the command prints the hooks line (checked by flipping the sentence: the test fails); the `tests/board-deploy.test.mjs` title now says the command only names line 3. No code, Worker or pinned file changes; tests and docs only.
- A new card's id must be one the probe can read, and a refused close says what is missing (idle-stall-counts-done-cards, #C949). The probe (`collector/state-schema.mjs` `CARD_ID`) reads ids of up to 5 hyphen-separated words, each up to 16 letters or digits, 40 characters in all; the store used to accept up to 64, so a longer id (#C896's six words) got no `cards.<id>` evidence row and a landed card was never seen. `createCard` now refuses such an id with rule `card-id` and says why (`PROBE_CARD_ID` in `worker/board-rules.mjs`, a copy of the probe's pattern because the Worker is bundled without `collector/`; a test holds the two equal). Cards that already exist are not touched, and every id the probe reads today is still allowed. The card-done refusals are split: `done_evidence` without `done` says to send `done: true` with it, and `done: false` says a write never reopens a done card (it used to read as "already done" for both). Not code: the live connector's `card_update` lists no `done` or `done_evidence` while the source does; see the card for which side is stale. Tests: `tests/close-from-every-door.test.mjs` (both connector doors list the fields; a close with evidence works from the shared door, Manager's door and the Access path; a done card is not reopened or closed twice; the id rule and its parity with the probe's; the refusal texts).

### Fixed

- The owner-phone-push cron test no longer fails by chance (push-test-flaky-bytes, #C950; it failed about 0.3% of runs). It searched the random encrypted bytes of each push for the text `#T`, which those bytes held by chance. It now opens each sealed push with the receiving device's own key (RFC 8291, one record) and checks the plaintext: exactly the four fields `title`, `body`, `url` and `tag`, none of the ask's title or text, and the ask's own number as the only thread id; and that what was sent is not the plaintext. A leaked title, a fifth field or another thread id fails it every time. Test-only: no Worker, probe, gate or hook file changes. Test: `tests/owner-phone-push.test.mjs`.
