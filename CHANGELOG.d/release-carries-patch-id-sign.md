- The release tool carries a signed commit's PASS and SECURE to its plain re-cut onto a newer main, on facts it reads itself (release-carries-patch-id-sign, #C1026; Security's conditions on the design). Only for a single commit directly on `origin/main` whose full message (every trailer) equals the signed commit's, whose changed paths, modes and blobs are equal (a delete or a rename counts as delete plus add), and for which no changed path differs between the two parents; every changed path must be under `tests/`, `docs/`, `CHANGELOG.d/` or `page/` (fixed lists in code: never `worker/`, `hooks/`, `gate/`, `collector/`, `keeper/`, `scripts/`, `.github/`, `wrangler*`, `package*.json`, any dotfile, a symbolic link or a submodule, nothing in the owner's closure), and `page/` only when the landings between the parents touched nothing under `page/` or `worker/`. The original must hold a real PASS and SECURE on its exact sha from origin's notes (a carried commit gets no note, so there is no chain), and if ANY commit with that Board-Id on an origin build branch outside main has a note whose first line is not PASS (Checker) or SECURE (Security) (FINDINGS, STOP, RISKS, withdrawn), nothing is carried. Release runs the full suite on the re-cut tip's own snapshot and refuses on red, and prints per carried commit the original's full sha, both note first lines, the paths and the landings range, then `carried: self-deploy will refuse until signed`: `scripts/self-deploy-gate.mjs` is not taught the carry (docs/self-deploy.md says so). A stack is never carried. Tests: `tests/release-carry.test.mjs` on temporary repositories (mutation-checked: 21 guards, each failing a test). `scripts/board-release.mjs` is owner-pinned: this needs an owner pack and Security's review of the verdict code.
