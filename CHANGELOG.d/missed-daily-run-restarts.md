- A missed daily product test run starts itself, and a finished ship CI wakes Release (missed-daily-run-restarts, #C1105). On 11-16 the daily full browser run never fired after the Mac update, and Release sat on a v1.212.4 candidate whose CI had finished green. (1) When the usage job reads the daily run as "missed", it starts it once by hand (`gh workflow run daily-e2e.yml --ref main` in the product's clone; `e2eStep` in `collector/probe-evidence.mjs`); the start is kept beside the answer (`startedAt` in e2e.json) and stands for the whole miss, so a slow run is never started twice, a failed start is logged and tried again 30 minutes later, and a reading that is not missed clears it. (2) The dispatch wakes Release once when a ship candidate's CI run finishes (`shipCiDone` in `collector/store-dispatch.mjs`): green when the candidate's run reads passed, red when a candidate it saw is gone and its version is not the live one (the line says a merge that went by between two reads looks the same); a candidate gone because its version went live is done silently. The turn is a card `shipci-v<x>-<y>-<z>-green|red`, kept as `shipci` in dispatch-state.json, and holds until Release has worked after the wake. Ships: the owner's install (the pinned `collector/probe-evidence.mjs`, `collector/store-dispatch.mjs`, `gate/reset.mjs`). Tests: `tests/missed-daily-run-restarts.test.mjs` and `tests/ship-ci-wakes-release.test.mjs`.
