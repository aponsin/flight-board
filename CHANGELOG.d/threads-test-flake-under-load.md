- `tests/threads.test.mjs` no longer crashes node under load (threads-test-flake-under-load, #C1370). Checker 2 saw it fail once at file level, with no assertion. It reproduces: run alone the file passes, but with 12 CPU burners and 60 to 80 copies at once, 5 to 20 percent of runs die with SIGSEGV (a macOS crash report names it: node 24.21.0 on arm64, a V8 mark-compact garbage collection that ran inside `vm.Script::Run`, walking a stack frame, faulting at address 0xe), so node:test reports only "test failed". It is not the clock, a temp folder or a timeout: the same crash happens bare, without the suite wrapper's preload, and with no node:test marker; `--jitless` or `--single-threaded-gc` makes it vanish (0 of 80 each). The file calls `loadNames` about 30 times and every call compiled and ran the whole 3800-line page script, so it allocates the most while GC can run in the middle of a script run. `tests/harness.mjs` now compiles the page script once per run and runs it in each new context, with only the short tail naming what to expose compiled per call: 0 crashes in 160 runs under the same load, and the file runs in 93 ms, not 147. New `tests/harness-load-names.test.mjs` holds what the change must not break (each load is its own world; what is exposed is what was named; globals reach only their own load). The crash itself cannot be asserted, so a different file that loads the page many times could still meet the same V8 bug; the remedy for that is a newer node, or a retry of a file killed by a signal in `scripts/test-run.mjs` (not part of this card). Tests only (mutation-checked: loading every call into the first context fails two of the three new tests).
