- A product card whose commit reached main behind a merge can now read live (live-behind-merge, #C1376, Director's audit #C1375, case 4). The version rule of #C1278 looked for the version commit with `git log --first-parent --ancestry-path <commit>..<live>`; for a card whose commit went to main inside a group, under the head main merged (fixture d5af0dd8 under group head c6b160f0), git judges the ancestry path along the first-parent line only, which that commit is not on, so the search answered nothing and #C1315, #C1320 to #C1323, #C1333 and #C1224 could never read live (without `--first-parent` it finds 7 versions). `versionAfter` in `collector/state.mjs` now asks two things apart: main's first-parent commits after the card's commit, oldest first, and the set of commits that descend from it; the first main-line commit in that set that names a version is the version it went live in, so a commit main took directly gives what it gave before, and a commit in no version yet still stays at ship. The meaning of live in DATA.md is unchanged: this is a bug fix. New `tests/live-behind-merge.test.mjs` (real git fixtures: a direct commit, a commit behind a merge, a commit in no version yet, and the version after it is never an earlier one); mutation-checked: the old search fails the commit-behind-a-merge test.
