- `npm test` no longer fills the disk with the tests' temp folders (board-tests-clean-tmp, #C1059; the temp dir held card-eta-wrap-* 5.8 GB and tmp.* 14.2 GB, besides fb-, publish-, board-release- and race-). `npm test` now runs `scripts/test-run.mjs`: the suite runs with TMPDIR set to a fresh folder of its own, and a preload (`scripts/test-tmp-clean.mjs`, also given to the node processes a test starts through NODE_OPTIONS) removes at process exit every folder made with mkdtemp, mkdtempSync or fs.promises.mkdtemp directly in that folder, so no test has to remove its own and nothing outside the run's folder is ever touched. Whatever is still left (a folder made with mkdirSync, a shell's mktemp, a child's own TMPDIR) is named by prefix with counts and sizes, removed, and fails the run (exit 1), so a new kind of leak is found, not hidden. Before: 698 entries, 170 MB and 144 prefixes per run; after: none. `scripts/board-release.mjs` is not changed (owner-pinned): its snapshot folders, left when it ends with process.exit, are cleaned from outside. The script runs itself when node was started on it, compared by real path on both sides (Checker 2's F1: through a symlinked path the plain comparison was false, so `node <symlink>/scripts/test-run.mjs tests/missing.test.mjs` ran nothing and exited 0). Tests: `tests/test-run-leftovers.test.mjs` (mutation-checked: recording folders outside the run's folder fails the "never one elsewhere" test; not passing the preload to child processes fails the "node process it starts" test; the plain comparison again fails the symlinked-path test; the leftover exit made `left.length ? 0 : 0` fails the test that runs the script on tests that pass but leave a folder, which must exit 1 with the TEST TEMP LEFTOVERS line on stderr: Checker 2's F2). The `pair-header-lists-all-cards` test passed 3 of 3 alone inside the wrapper (about 12 s), and failed once in four full runs under load ("could not parse HEAD" on its temp repo, 35 s against 9 s alone); that is the known load flake (#C1041's note had it failing under load before this change), and it is not fixed here.
