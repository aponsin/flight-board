- The board's refresh no longer breaks text selection, makes the page jump or disturbs typing (board-select-text-stable, #C1229; the owner: copying worked about one time in five, the page jumped while he scrolled to read, and moving the cursor back a few lines in a box went wrong). All in `page/board.template.html`. A redraw of the board, the done list, the threads, Needs you, the team notes and the resolved list goes through `patchHtml`, which leaves every top-level row whose html did not change as it is (the same node, so a selection in a step, a message or a Copy box inside it stays) and replaces only the rows that changed; a fold the owner opened or a note he is typing no longer makes a row look changed. In a row that did change, a text box with focus or with unsent text is carried into the new row as the same element, with its value, cursor, selection, scroll and focus (`keep()` and Needs you no longer set a value or the focus again when the box is already as it was, which moved the cursor to the end). A redraw waits only while a pointer is down (a drag in progress), polling at the batch pace; a cancelled pointer, a drag end or a lost window focus end the wait. A selection that stays (⌘C does not clear it) never holds the board (Checker 2's F1): the one row it sits in is left as it is, stale, until the selection goes, when `selectionchange` draws it, and every other row is drawn as usual. A copy ends the hold (Manager, on Checker 2's F1): the `copy` event and a click on a Copy button release it, the held row is drawn, and a new press starts the hold again; there is no timeout, so a slow selection keeps its hold. While a row is held or a drag is on, a small fixed note says "Updates paused while text is selected — click anywhere to resume" (`#holdnote`). Rows are matched by `data-id` (else `id`, else place), so a row added or taken away above leaves the rows below it untouched; a box is carried only into a box with the same id (Security's F1). Every redraw, the 15 s ship redraw too, keeps one row in place on screen: the row he is in, else the row he last pointed at while it is on screen, else the topmost row in view, and scrolls by the shift so content added above does not move what he reads (not left to the browser's own overflow-anchor). Needs you wires its buttons and folds once per row, since rows now survive a redraw. Ships: a page change, so a pack with a hooks step.
