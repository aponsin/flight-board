- The board's refresh no longer breaks text selection, makes the page jump or disturbs typing (board-select-text-stable, #C1229; the owner: copying worked about one time in five, the page jumped while he scrolled to read, and moving the cursor back a few lines in a box went wrong). All in `page/board.template.html`. A redraw of the board, the done list, the threads, Needs you, the team notes and the resolved list goes through `patchHtml`, which leaves every top-level row whose html did not change as it is (the same node, so a selection in a step, a message or a Copy box inside it stays) and replaces only the rows that changed; a fold the owner opened or a note he is typing no longer makes a row look changed. In a row that did change, a text box with focus or with unsent text is carried into the new row as the same element, with its value, cursor, selection, scroll and focus (`keep()` and Needs you no longer set a value or the focus again when the box is already as it was, which moved the cursor to the end). A redraw waits while text is selected or a pointer is down (a drag in progress), polling at the batch pace, and draws once the selection clears or the pointer is up; a click with no selection holds nothing, and a cancelled pointer, a drag end or a lost window focus end the wait. Every redraw, the 15 s ship redraw too, keeps one row in place on screen: the row he is in, else the row he last pointed at while it is on screen, else the topmost row in view, and scrolls by the shift so content added above does not move what he reads (not left to the browser's own overflow-anchor). Needs you wires its buttons and folds once per row, since rows now survive a redraw. Ships: a page change, so a pack with a hooks step.
