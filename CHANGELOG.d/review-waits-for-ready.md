- A pushed tip wakes no reviewer until the builder's READY signal covers it (review-waits-for-ready, #C1066). In a stack-mode repository the dispatch gives a pushed card no review turn while the probe marks it `stackHold` (no stack-ready signal covers its tip), with or without a declared partner: before, only a card with a partner waiting was held, so a work-in-progress start push (11-12: Checker woke for #C1059's start push; 11-16: an empty start commit kept waking Security on every re-arm) went straight to the review lanes. A tip with the signal on it (stack-ready writes it only when no card of the batch or stack is waiting) is reviewed as before, and so is every other card of its batch or declared partners (`depends_on`, either way): the signal covers one head and ends the wait of the rest, which the probe now reads (Checker 2's M1); a second push after the signal is a new tip and waits for its own; the switch off and product repositories read as today. The probe's `stackHold` reading changes (the peer rule), so the probe install carries it too. Must land before the push-first hook (#C1065). Tests: `tests/stack-ready-hold.test.mjs`, `tests/batch-not-ready-alone.test.mjs`.
