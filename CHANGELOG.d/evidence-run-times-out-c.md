- The probe's state child runs far fewer processes a run, so the evidence job finishes well inside its limit (evidence-run-times-out #C996, part 3's rest). Three cuts, none changing a reading: (1) a trailer index: one `git log` of main's Board-Id commits gives every open card its head, where each card asked git once or more (a card the index lacks is none when the list was whole, and is asked alone when it was cut at 5000 commits or git failed); (2) a per-run read memo: each distinct read (merge-base, rev-list, log, diff, show, cat-file, rev-parse, notes list or show) runs once and a failure is kept too, while fetch and any write run every time; (3) one batched `gh run list` (the newest 100 runs) gives each card its CI reading by commit, where each card asked gh for its own; a commit the list lacks is asked alone, the 10-calls-a-run cap and the back-off hold, and a failed list is one failed call. A run whose cards are all cached asks gh nothing. The stopgap (a 2-minute evidence interval, the 170 s limit and the 5-minute edges on the page) stays until the one-day timing line shows the cut; returning to every-minute updates is a separate step. Tests: `tests/state-fewer-processes.test.mjs` (fake and real git: the same card states, fewer processes, the same count for 4 cards as for 40).
