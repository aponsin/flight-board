- A dispatch watch started from an old install ends itself and says so (#C1158): on 11-17 a start push woke the reviewers although #C1139 stops that, because their `--once` watches had been started from older installs, which have no such rule, and a `--once` watch keeps the code it started with until it fires. `scripts/wake-watch.mjs --role <Role> --once` now reads the install folder it runs from and the one the Stop hook pins (the single `gate/stop.mjs` entry in `~/.claude/settings.json`), and when they differ it prints `wake-watch: stale pin: this watch runs from install <sha> but the Stop hook pins <sha>; ...`, removes its pid file and ends, so the role re-arms on the path its Stop hook prints. It is told once per role and pair of installs: a role that re-arms from the same stale path keeps running, so this cannot loop. A watch run from a checkout, or a settings file with no single pin, is left alone. Every DISPATCH line a watch prints from an install folder now ends with `[watch install <sha>]`, so a reader can see which code decided. `scripts/wake-watch.mjs` is a pinned file: it rides the next owner pack. Tests: `tests/watch-ends-on-stale-pin.test.mjs` (pure functions, and the command run as an owner runs it from a copy in an install folder; mutation check: with the stale exit off the stale watch is killed after 5 s and the test fails, and with the once-per-pair guard off the same-path re-arm ends again).
