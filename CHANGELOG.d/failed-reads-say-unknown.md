- A git or GitHub read that fails is no longer read as "no": the card says `unknown` and names what it could not read (failed-reads-say-unknown, #C1387, first half of the plan's "unknown for every failed read"; notes, install, the pair folder and CI are #C1395). Until now `collector/state.mjs` folded any failed call into the answer "no" (`ok()`), so a git timeout or exit 128 under load read a card as not on main, not deployed, no version yet or outside its stack, and a failed behind-main call sent a signed card back to its builder for a re-cut. Now git's exit 1 is the only "no" (the existing `ancestry()` rule, used at every site below) and any other failure marks the card's new optional `unread` field (a list of source words from a fixed list in `collector/state-schema.mjs`, validated, carried by `pickState`) with the source: `main` (the tip's place on main, the landed-as-other-commits search, the trailer search on main, the ship lines, a newer tip's place), `deploy` (the head in the live commit, the live commit itself when the deploy-run list or the installed-tree ancestry could not be read), `version` (the version commit after the head), `stack` (the stack's ancestry, the stack's and a group's branch commits, the merged-branch list), and the minor `start` (empty start commit) and `behind` (behind main). `worker/reading.mjs` reads a non-empty `unread` of main, deploy, version or stack as state `unknown` with a why naming it ("could not read main"), never working and never done; a stale reading with an earlier good one keeps its own rule, and `start` and `behind` only set the flag, never the state (a failed behind-main call answers neither: no re-cut). The page already draws `unknown` as the plain ring, so no page change; no per-card last-good file. `collector/state.mjs` and `collector/state-schema.mjs` are pinned probe code: this ships with the next pack. New `tests/failed-reads-say-unknown.test.mjs` (one failing read per site gives `unread` and an unknown reading, a good read is unchanged, exit 1 still means no); `tests/store-live-from-deploy.test.mjs` restates one source-text pattern for the new argument; mutation-checked: putting `ok()` back at the behind-main site and at the deploy ancestry site fails two tests each.
