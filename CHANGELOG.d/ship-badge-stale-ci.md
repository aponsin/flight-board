- The "Not now: Ship vX CI running" badge clears once the ship is live (ship-badge-stale-ci #C1038). On 2026-11-12 it read "Ship v1.210.5 CI running" for a ship that was live with main's CI green, because the badge waited on a candidate branch that a merge never makes an ancestor of main, and the board holds no ship record to close it by. Now the probe closes a candidate by main's own deploy: it reads the commit of main's newest successful deploy run back along its first parents (`versionsOn` in `collector/state.mjs`, with the config's `versionPattern`), and a candidate whose version that history names is dropped from the state's `ship`, whatever its own run reads. No deploy run read, or no `versionPattern`: the candidate stands, as before (the badge errs toward "not now"). A newer candidate is never hidden by an older shipped one. Tests: `tests/ship-candidate.test.mjs` (a finished-green ship with no record, and the reader). The probe (`collector/state.mjs`) is pinned, so it ships with the next pack.
