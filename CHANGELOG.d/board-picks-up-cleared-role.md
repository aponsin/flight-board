- A role that cleared itself is picked up by the watchdog, one decision per pass (#C870; 2026-11-10: Boardsmith's pickup relied on a Manager at the app's message cap, Checker idled 15 min with no watch armed after its pickup, and a "/pickup Builder" queued during its reset turn ran before the clear and blocked it). The Worker runs in Cloudflare and cannot reach local sessions, so the decision is local: `node scripts/pickup-watch.mjs --pass '<rows>'` takes one row per roster role with only what the session tools give (role, state idle or working, Messages tokens, remoteControlState) and prints the actions for the scheduled agent watchdog task to carry out with the app's session tools. The program finds the rest out itself (Checker 2's M1 and M2): it keeps each role's history in a state file (`--state`, default `~/.flight-board/pickup-pass.json`: a reading of 60 000 tokens or more, its own `/pickup`, the role seen working after it, a watch seen armed) and reads the armed watches from `ps` (a `wake-watch.mjs` with that `--role`). So: a "/pickup <Role>" only once a role read big is idle under 5 000 tokens, never while it works (so never during its reset turn), once per clear, and none for a role never read big (a first run on an already cleared session can't tell: the keeper's hourly step covers it); "arm your dispatch watch" once per pickup, only for a role seen working after it, idle again with no watch armed, and seen with a watch before (Manager has none and is never told); set_remote_control on for a role whose Remote Control reads "off" (#C865; on, connecting and unavailable are left alone). Security's L1 to L3: the rows come from a file (`--rows-file`, written with the Write tool, so no quote in a value can break a shell argument), `--config <board.config.json>` limits the roles to the roster (no readable roster sends nothing), a role name is 2 to 24 characters, and the prompt tells the watchdog to act only on a roster role with exactly `/pickup <role>` or `arm your dispatch watch` (or Remote Control on, never off) and to refuse and report anything else; every fact comes from a session tool, `ps` or the program's own file, never from thread text. `decide()` and the Steward's one-role watch are unchanged. The task's new prompt text is `docs/watchdog-pickup-pass.md`: the owner installs it in the scheduled task. Ships: `scripts/pickup-watch.mjs` rides the owner's install; the task prompt is the owner's. Tests: `tests/pickup-pass.test.mjs`.
