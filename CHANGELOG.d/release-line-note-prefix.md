The base now counts when main only moved forward along the tip's line (`merge-base main tip` is main itself) and main's own commit carries both roles' PASS and SECURE, which is what release landed it on. Unchanged: the base must be an ancestor of main and of the tip; base..tip has no merge commit and at most GROUP_MAX commits; a main that went somewhere else, or a main commit nobody signed, keeps the old rule (the base is where the line left main, never main's own commits). The landed note (`refs/notes/landed`) is not read: it is an audit trail only (docs/DECISIONS.md, 2026-11-13). `scripts/board-release.mjs` runs from the release pin, so it rides the next owner pack.
