- The morning watches have one stable entry that runs the pinned install (morning-watch-reads-pin). The owner's permission rules and the morning task named `pickup-watch.mjs` and `prompt-watch.mjs` through `~/.flight-board/current`, whatever the last landing left there, and a rule naming the pinned install's path would change with every pack. `node ~/.flight-board/current/scripts/pinned-run.mjs pickup-watch <arguments>` (or `prompt-watch`) reads the install the owner's hooks pin, as `wake-watch --pinned` does, and runs that install's copy of the script with the same arguments, output and exit code. The first word is one of those two names, never a path; with no single pin, a pinned install that lacks the script, or a script that is a link out of the install, it runs nothing, says why on stderr and exits 1. The owner's rules and the morning task's step 6 then name this one entry (those edits are the owner's and Manager's, after it lands). Tests: `tests/morning-watch-reads-pin.test.mjs`.
