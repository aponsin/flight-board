- The landing job's own file runs from the owner's installed copy, not from the link: `scripts/make-pair.mjs` counts `scripts/board-land.mjs` among the hook entries, so a pack that changes the land job or a file it imports always carries the hooks step that creates the pinned install, and it also writes a land step, `board-store-land-<pair>.mjs` (from `scripts/pair/land.template.mjs`), as line 4 of the steps file. The step points the LaunchAgent `com.flight-board.store.land` at `~/.flight-board/install/<the pack's main>/scripts/board-land.mjs` instead of `~/.flight-board/current/...`: it refuses unless that file exists, finds the one place the LaunchAgent's file names board-land.mjs (any other shape is refused with nothing changed), keeps a backup, checks the new file with plutil, reloads the job and checks launchd has it, reads the file back, and has an undo; run twice it changes nothing more. A pack that does not touch the land job writes no land step (land-job-runs-pinned-copy, #C1140). Ships: the owner's pack (the first one that carries the land job after this: the new line 4, then nothing more to install by hand). Tests: `tests/land-job-runs-pinned-copy.test.mjs`.
