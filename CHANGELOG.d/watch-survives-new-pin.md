- A role's watch follows a new install by itself instead of ending "stale pin" (watch-survives-new-pin, #C1240; on 11-18 six pack installs ended every role's dispatch watch with the stale-pin line, Triage, Demos and Sales re-armed by hand several times and asked whether something looped, and Triage stopped re-arming). A watch armed with `--pinned` now runs as the child of a small launcher in `scripts/wake-watch.mjs` that stays up. When the settings' pin moves, the child ends quietly with exit code 75 (`STALE_EXIT`, told so by `WAKE_WATCH_FOLLOW=1` in its environment) and prints nothing, so no agent is woken for it; the launcher reads the settings again and starts the new pin's copy (`followStep`). The safety of the pin check is unchanged: the launcher only ever starts `<install root>/<the one sha the settings pin>/scripts/wake-watch.mjs` (`pinnedLaunch`), a pin whose install has no such file ends the launcher with a line, and more than 3 pin changes inside 60 seconds end it with a line too (a loop, not an install). A watch armed on a path with no `--pinned` keeps the old behaviour: the stale line, then it ends. A DISPATCH line still ends the watch and wakes the role, as before. Takes effect for a role that arms with `--pinned` from an install that has this change. Ships: gate and script code, so a pack with a hooks step. Tests: `tests/wake-watch-follow-pin.test.mjs`.
