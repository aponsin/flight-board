- `scripts/test-run.mjs` runs a test file once more when a signal killed it (test-run-retry-on-signal, #C1371). The node 24.21.0 V8 crash under load (#C1370) kills a test file with SIGSEGV, and node:test then says only "test failed", the same words as for a file that called `process.exit(3)`, so a green change could fail a full suite for no reason of its own. Each test file's process now leaves a marker (`scripts/test-tmp-clean.mjs`, in a folder of the run's own) when it starts and removes it when it ends by itself, by a failing test or by `process.exit`; a process a signal kills runs no exit handler, so its marker stays and names the file. The wrapper runs each such file again, alone: the second run passing keeps the suite green and prints two loud lines (`TEST FILE KILLED BY A SIGNAL: ...` and `WARNING: ... passed on its second run ...`, with the crash-report folder to look in); a second death or a failure fails the suite and lists `FAILED <file>: killed by a signal on both runs`. A failing assertion, a `process.exit` and every other failing file are never retried and still fail the suite, even when a killed file passed on its second run. New `tests/test-run-retries-signal.test.mjs` runs real fixture files: killed once then green with the warning, killed twice, assertion failure run once, `process.exit(3)` run once, a retried-green file beside a real failure, and the marker list. Tests and scripts only (mutation-checked: the marker not removed at exit fails four of the six tests, and a retry always counted as passed fails the killed-twice test).
