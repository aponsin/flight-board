- A product card closes when it reads live, not when its commit lands, and never waits on an install (product-card-closes-on-live, #C1378, the owner's pick A on #T2194, Director's audit #C1375 rule 4). Two rules read "a card with a repository word" as a board-like card: the Worker opened an owner's-install wait for any card at ship and on main (93 product cards got one, and the referral group read "Waits on the owner's install"), and #C1104 part 2 closed a card of any other named repository the moment its commit reached main (71 product cards closed at "ship", before their deploy, so their reading froze there and "done" no longer meant live for the product). One table now answers it: `repoKind(word)` in `worker/board-rules.mjs` is "board" for the board's own words (and for no word, as before) and "product" for any other named repository. The install wait (`installWaitStep`) opens for the board only, and a wait an earlier rule opened ends at the card's next reading; `closesAtLanding` is removed, so the store closes a card only on a `live` reading, with the commit's link as evidence, the same for both kinds.
