- The watchdog's pickup pass fits the scheduled task's own rules, so its doc (`docs/watchdog-pickup-pass.md`) can be pasted in and a run finishes with no prompt: `scripts/pickup-watch.mjs --pass x --rows '<role>,<state>,<tokens>,<remoteControl>;...' --config <board.config.json>` takes the rows as one argument of plain words and numbers (a row of any other shape is dropped, so no quote or shell character can reach the command), so no file tool is used (#C443); each printed action carries `session`, the id the config's `rosterSessions` holds for the role (null when it holds none), so the run reads no config file either; the doc names the ToolSearch line with `get_usage`, `get_session` and `set_remote_control`, adds "Checker 2" to the title list, and names the one command to pre-approve (watchdog-pickup-pass-fits-task, #C1132). Because the command is pre-approved as a prefix rule (any arguments), `--pass` takes no path outside the board's own folder: `--state` only as `~/.flight-board/pickup-pass.json` (the default; a symlink is refused), `--config` only as a file named `board.config.json`, and not `--rows` with `--rows-file` (otherwise it prints `[]`, says why on stderr and writes nothing; Security's M1 and L1 on d71cebd6).
