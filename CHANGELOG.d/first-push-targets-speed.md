- The first-push guard reads a long Bash command in linear time (first-push-targets-speed, #C1291; Security's INFO on #C1289: `bashTargets` took about 2.7 s on a contrived 200 KB command, and fails open). `gate/first-push.mjs`: one helper, `replaceHeredocs`, replaces the heredoc regex that `bashTargets` and the commit check both used. The regex looked for a heredoc's closing line from every "<<" to the end of the command, so many unterminated "<<" cost time squared; the helper lists the possible closing lines once and each "<<" takes the first one after its own line, and it reads exactly as the regex did (the tag may back off to a shorter start of the word when it is not quoted; the closing line is never the line right after the "<<" line). Unchanged: which writes the guard reads, which commits are refused. The hook changes, so it rides the next board pack with a hooks step, in the same pack as #C1289. Tests: `tests/first-push-targets-speed.test.mjs` (20000 random commands read the same as the old regex; six shapes of 200 KB commands each read in under a second; what the guard reads is unchanged).
