- The board checks its own readings against git (truth-check-job, #C1386, step 4 of the one reading per card). A step of the collector's usage job (no new LaunchAgent) asks the Worker for every card's reading (new probe-only route `GET /api/probe/readings`, which returns the compat answer's readings and the time, nothing else), asks git its own questions for each card (it imports neither `reading.mjs` nor `collector/state.mjs`, so a mistake in the reading cannot hide in the check), and compares the two: whether a card's version is on main, whether it is inside a shipped version, whether it reads live or done. Each difference is one named item with both values. A difference counts only when two runs in a row see the same one (the first run writes it with count 0, the second raises it), so a read taken mid-landing does not raise it; a clean run writes count 0 so the line clears. At most 10 items are written; `count` is the whole number. A reading that says it cannot be trusted (stale or unknown) is skipped, so is a version commit younger than the young-commit window, and a closed card whose reading is not done is compared on done only after an hour closed. A failed git or folder read gives "unread", never a difference, and the step never throws: a failing step does not fail the usage job and writes nothing when the readings cannot be fetched. The result is the evidence key `truth` (the Worker's `truthShape` refuses any other shape as `truth-shape`; only the probe may write it; `probeDoc` passes it to the page only while fresh). The page draws it as one red line beside the e2e line in the stuck strip (the count and the first 5 items, the card number as plain text, "and N more" past 5, text escaped, nothing when absent, stale or count 0). While it holds, one wake goes to the steward through `stall_wakes` (one row per spell, deleted at count 0 so a new spell wakes again). Ships with a Worker deploy (route and evidence key), the page and a probe tree step; no migration. New tests: `tests/truth-check.test.mjs` (the facts on a recorded repository, the two-run rule, the caps, failed reads, and a mutation test that puts `--first-parent` back into `collector/state.mjs` `versionAfter` and sees the check report the card behind a merge), `tests/truth-evidence-board.test.mjs`, `tests/truth-line-board.test.mjs`; the new constants are on the knobs lint's FIXED list with reasons.
