- A card is not read as live while a part of it is not on main (plan-part-on-main, #C890, half 2 of #C863). A part is named by the word "part" and a commit sha in the card's next_note ("part 1a2b3c4", 7 to 40 hex characters); every other sha in a note (a superseded tip, a review tip, an old stack) is ignored. While any marked sha is not an ancestor of main, the probe holds the card at ship instead of live and shows which sha is missing (`partsMissing` on its reading); a sha the repository cannot find counts as not on main. The marked parts are read whenever the card's head is on main, not only at a would-be-live reading, so `partsMissing` also names a missing part on a card whose commit on main is code and reads ship (the board closes a card of a repository with no install step when its commit lands, #C1104, and must not close one with a part still off main; Checker 2's M1 on #C1104); the phase is held at ship only for a would-be-live reading, as before. A note with no marker behaves as before. Probe only (a probe install, no Worker deploy). Tests: `tests/plan-part-on-main.test.mjs`.
