- The board checks each role's model and effort on every evidence run and shows a drift in red with the fix (sessions-checked-each-run, #C1111). Models and effort drift after a crash and were re-checked by hand. The board config gets `roleSessions: [{ role, model?, effort? }]` (effort: low, medium, high, xhigh or max; a role or field left out is not checked). The app's session file of a role's newest open session (title exactly the role name; an archived one is not read) carries the model and effort it runs on; `appSessions` now keeps the effort as a plain word beside the model. The evidence job (`collector/role-sessions.mjs`) posts one key, `session.checks` `{ at, roles: [{ role, chosen, ran, chosenEffort, ranEffort, at }] }`, with the late writes before live; the Worker checks its shape (`sessionChecksShape`) and the probe document carries it at any age. The Crew panel shows one chip per role: green "✓ model · effort", red with the exact fix ("model X, chosen Y: set the model to Y in the app's model menu"; the same for effort), amber for no open session or a chosen field the file did not give, grey when nothing is chosen, and "session reading old" past 36 hours. Remote Control is not part of this: the app keeps that switch where a script cannot read it (#C865's spike), so it stays the pickup skill's step until a session-run check is built. Ships as a Worker deploy and the owner's install (the pinned `collector/state.mjs`, `collector/probe-evidence.mjs`, `scripts/config.mjs`), and the owner writes `roleSessions` into the board config. Tests: `tests/sessions-checked-each-run.test.mjs`.
