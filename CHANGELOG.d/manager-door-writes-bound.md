- Every write on Manager's connector door must name the caller's own session, checked against the door session as `read_inbox` is. A write that names none, or another one, is refused (`door-session-mismatch`), writes nothing and is logged; the expected id is never echoed. With no door session set a named session goes through, so a deploy never shuts Manager out. `session` is taken off before the tool sees it and stored nowhere, and `tools/list` on Manager's door shows it as required on each write tool. Not covered: `read_view`, `read_inbox` and `set_door_session` (their own guards); the shared door and the Access path are unchanged. Before, a session that was not Manager's could post through Manager's connector and the board signed it "Manager" (and the owner got a reply badge for it). Ships: a Worker deploy; Manager's own calls need `session` once it is live. Tests: `tests/manager-door-writes-bound.test.mjs` (mutation-checked); four older tests now name a session on Manager's door (manager-door-writes-bound, #C1298).
