- An agent puts a file that is already on the Mac into a thread or an ask in one step (agent-attaches-local-file, #C1056; the owner, 11-12: pictures agents make reached him in the Claude app but not in the board thread as options, because file_put takes base64 typed through the model, so a 15 KB picture failed or cost about 20k tokens and agents gave up). `node scripts/put-file.mjs --config <the board config> --env <the probe's env file> <path> [--name <name>]` stores the file and prints `FILE <id> <name> <type> <size>`; the agent then names the id in its own post or ask (`screenshots: ["<id>"]`, or `"<id> A: label"` under a Decision option). The bytes never pass through a model. Auth is the probe's own Access service token, the one credential this Mac already holds for the board (BOARD_SERVICE_TOKEN_ID and BOARD_SERVICE_TOKEN_SECRET in the env file, which must be readable by its owner alone; nothing new is made, kept or typed in chat). The Worker gets one narrow route, `POST /api/probe/file`, role probe only: it stores a file and returns the id and nothing else, with putFile's own rules (the file types, the bytes sniffed against the type, 15 MB, the store's size and the day's cap, which the probe shares with all agents so the route adds nothing to it). The probe still cannot read a file back, open the page or write a thread. The script is narrow on purpose, because a stored file is readable by every agent and person past Access and the board's own folder also holds secrets (the env file, board.private.json): the real path (links resolved) must be inside the folder that holds the board config, or inside a folder the config lists under the new optional `fileRoots` (up to 5, absolute or `~/`, none with `..`; none by default; never a repository checkout), so no folder is named in the code and the command line cannot add one; no part of the path below that folder may start with a dot or contain private, secret, token, credential, password, env, key or cookie as a word; the file must be a plain file that is not owner-only (mode 0600 marks a secret here), not empty, within the cap, and a picture, a PDF or plain text, markdown or csv (no JSON). Failures say why in a few words and never carry the token. Ships: a Worker deploy (the route), and the script (nothing to install: it runs from a checkout or the linked copy). The owner's config needs nothing to start: the config's own folder is the one root; a `fileRoots` entry is only for a second folder, such as a mockups folder. Security weighs the widening: the probe's token can now also store a capped file; anyone who can read the env file as the Mac's user already held that token.
