- Shipped branches are listed and deleted through one weekly Terminal ask the board makes (shipped-branches-swept, #C1112). The rule was "delete shipped branches without asking", but the app blocks agents from doing it, so Manager batched them into a Terminal item by hand and forgot. Now the evidence job (`collector/shipped-branches.mjs`, at most every 6 hours, read-only git: `rev-parse` and `for-each-ref --merged`) lists, for the team's repository and each `collector.repos[]` entry that has a `~/` folder, the remote and local branches whose tip is already on main, and posts `branches.shipped` `{ at, repos: [{ name, dir, remote, main, remoteBranches: [{ name, sha }], localBranches }] }` (plain branch names only, the remote branch's tip sha for the delete's lease, 6 repositories and 60 branches of each kind at most). Never listed: main, dev, master, HEAD, the repository's own main, a branch cut at main's tip, a branch with commits main lacks, and the branch of a card that is not live yet, tied to the card as the board does (the branch's name, the Board-Id trailer of its tip, or a `#C<number>:` subject); the Worker's shape check refuses the same names, so a bad reading can never make a delete line for them. The store (`syncBranchSweep`, run by the probe's 20-second ask) raises ONE Terminal ask from a list under 2 days old, asked as the lead, titled "Shipped branches to delete: N on main already", with one `git -C <folder> push <remote> --force-with-lease=<branch>:<sha> ... --delete ...` line per 15 remote branches (a branch pushed again since the listing is not deleted) and one `git -C <folder> branch -d ...` per 15 local ones (`-d` refuses an unmerged branch); no second ask while one is open or within a week of the last. Ships as a Worker deploy and the owner's pack (the pinned `collector/probe-evidence.mjs`). Tests: `tests/shipped-branches-swept.test.mjs`.
