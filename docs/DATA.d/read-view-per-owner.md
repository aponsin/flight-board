- 2026-11-16: The `read_view` tool can be cut to what an agent can read (#C1089). The store's whole view is about 5.4 MB (4816 messages), so Ops could not list its own cards. The tool (`worker/board-worker.mjs`) now takes `owner_role`, `thread_id` and `summary`, and `viewForTool` (`worker/view-filter.mjs`, pure) shapes the answer after `readView` has built the whole view: `owner_role` gives that role's open cards (`done_at` empty, not dropped), the evidence of those cards only (`cards.<id>`, which the pickup digest reads for each card's phase) and the open asks (`closed_at` and `withdrawn_at` empty) it asked or that sit on one of those cards; `thread_id` gives the thread row and its messages (the thread is null and the messages empty for an unknown id); `summary: true` gives a summary (`tag`, `now`, `live`, `probe`, `wakeState`, `openCardsByRole`, `openCards`, `openAsks`, counts of threads and messages, a hint). With none of them the tool still returns the whole view, as before, because `scripts/pickup-digest.mjs` and `scripts/approvals-check.mjs` read cards, asks and evidence from it (Checker 2's F1: a summary there made every role's pickup print "None open."); the pickup moves to `owner_role` in its own card. `readView` itself, which the page, the probe, the dispatch and `/api/view` read, is not changed. No migration, table or column. Ships as a Worker deploy. Tests: `tests/read-view-filters.test.mjs`.
