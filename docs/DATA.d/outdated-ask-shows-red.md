- 2026-11-20: New ask state Outdated (#C1409): Manager's door (`ask_outdate`: id, reason of 1 to 300 characters, optional `replaced_by` = a replacement ask's number) calls off a Terminal, Action or Later ask that is open and unanswered; the store sets `outdated_at`, `outdated_by`, `outdated_reason` and `replaced_by` (new columns, migration 0041; `withdrawn_at` stays the owner's Withdraw of an approval) and does NOT close it, so it stays in the owner's lists until he closes it himself (Close / Got it). An outdated ask is owed by no one: no stall, wake, push, hold, "asked" gate, dispatch hold or count reads it as waiting, and a hold that ends on it has ended. The ask's served doc keeps `done` unset and adds `outdated: { at, by, reason, replacedBy? }` (replacedBy the replacement's ask number); the page draws it Outdated in red with the reason and a link to the replacement, its commands greyed with no Copy. An owner's answer to it is kept as for any ask and still wakes Manager, whose inbox answer carries `outdated_note` saying he answered a called-off ask.
