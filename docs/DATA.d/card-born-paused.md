- 2026-11-20: the card_create tool takes `paused` (true or false), as card_update does, and the store writes it in the card's own record (#C1348; #C1347, a follow-up that had to wait for a ship, was created and paused in a second write, and the dispatch watch sent it to Builder in the seconds between). The store already wrote a `paused` field on a new card; the tool's schema did not name it, so the connector refused it as an unknown field. A paused card still needs a current `next_note` saying why (the same rule as card_update's paused: `blocked-needs-note`), and a card refused for it is not written. A card made without `paused`, or with false, is dispatched as before; a paused card is never dispatched (the dispatch skips it) until it is unpaused. No migration, table or column. Ships: a Worker deploy. Tests: `tests/card-born-paused.test.mjs`
