- 2026-11-16: The pre-push content scan's phone rule skips a commit id (#C1096). About one commit id in a hundred holds ten digits in a row (main's tip on 11-16 was one: its first twelve characters held ten digits, then a letter), and `scripts/scan.mjs` read them as a phone number: a git note or a commit message naming that commit was refused, so Security's line notes from that fork point could not be pushed and Release's dry runs stopped on #C1091, #C1089 and #C1090. `scanText` now reads the line a second time with every whole hex token of 12 to 40 characters removed (`withoutCommitIds`: at least one letter a-f in it, no letter or digit touching it, a full stop after it allowed) and applies only the two phone patterns to that reading; the artifact-link, email, token and listed-word rules read the line as written. A bare digit run, a phone in any written shape, a token shorter than 12 or longer than 40 and a phone next to an id are still refused. `scripts/scan.mjs` is in `RELEASE_ENTRIES` (the release tool's own scan of what it lands runs the owner-installed copy, so that copy changes with the next owner pack); the pre-push hook (`.githooks/pre-push`) runs the pushing checkout's own copy, so it changes as soon as the checkout has this commit. No migration, table or column. Tests: `tests/scan-skips-commit-ids.test.mjs` (the strings are built from pieces: the repository's own scan reads the test file).
