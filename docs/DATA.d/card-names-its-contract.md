- 2026-11-17: A flight-board card names what it touches before the store accepts it (#C1169). On 11-17 Manager carded #C1168 against "Started = first push" (this file, the Started definition) without checking it, and added a Stalled exemption to #C1164 the same way; the owner asked that every card about the flight-board be checked against the first-level principles. A card has two new optional fields, `contract` (one line of up to 400 characters: the principle numbers and DATA.md rows or definitions the card touches) and `changes_definition` (true or false; stored as 1 or 0). Through the `card_create` tool a card whose repo is the board's own (`flight-board`, or a word the board reads as its own) is refused with the rule `card-contract` unless it has both; through `card_update` a write that changes such a card's summary must carry both in the same write. With `changes_definition` true the card also needs `from_thread`, the number of a thread that exists (the owner's decision), else it is refused with the rule `card-changes-definition` ("this changes <contract>: ask the owner first"). A product card, a write with no summary, and the store functions called without the tools' option are untouched; a card written before has neither field. Migration `0038_card_contract.sql` (two nullable columns). Tests: `tests/card-names-its-contract.test.mjs`. Touches principles 1 (a note is not a rule: the check is the store's) and 5 (refuse early); changes no definition in this file.
