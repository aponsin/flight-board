- 2026-11-20: The second half of "a failed read is never read as no" (#C1395; #C1387 did main, deploy, version and the stack). `unread` (`collector/state-schema.mjs`) now also carries `notes` (a `git notes show` that failed with any status but 1, for a card not on main), `install` (the card's landing could not be diffed or its commits on main searched, while the card is not yet deployed) and `pair` (the owner's pair folder or a git question about a pair could not be read, for a board card on main waiting at pack or install); `ci` is set when the card's own CI call failed. The Worker's reading (`worker/reading.mjs`) reads `notes`, `install` and `pair` like `main`, `deploy`, `version` and `stack`: state `unknown` with a why naming the source ("could not read the sign-offs", "the install state", "the deploy pairs"), never working and never done; `start`, `behind` and `ci` are flags only, and a live card is done whatever it could not read. CI's one word splits into four values, stored in the card's `ci` (the enum is now none, backoff, capped, unread, queued, running, passed, failed, cancelled) and in the ship record's `ci` (none, backoff, capped, unread, queued, running, passed): `none` is only "no run exists on the commit" (gh answered with an empty list); `backoff` is a call not made while GitHub's back-off lasts, `capped` a call not made past the run's call limit, `unread` a call that failed (never `failed`, which stays the run's own result); an answer that is none of these is `unread`. The ship tile's words add "CI check waiting", "CI check limit reached" and "CI not read" (plain, never red), and a ship candidate whose place on main could not be read stays and is marked `stale` (the page says "no fresh reading"). No card is made unknown by CI. Pinned probe code (`collector/state.mjs`, `collector/state-schema.mjs`, `collector/pairs.mjs`): ships with the next pack. Tests: `tests/failed-reads-notes-ci.test.mjs`.
