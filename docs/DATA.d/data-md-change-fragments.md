- 2026-11-16: Each card writes its "Changes" line to its own file, `docs/DATA.d/<card id>.md`, and a fold step joins them into this file (#C1090). On 11-16 every card appended its dated line at the end of `docs/DATA.md`, so each landing conflicted every waiting branch there (#C1075 was rebased and re-signed twice, for #C1081 and #C1083, and three more rebases followed the same day). The same cure as `CHANGELOG.d/` (#C1019): `scripts/data-fragments.mjs` (`--check`, `--write`, or no flag to print the result) reads `docs/DATA.d/*.md` (each file one line, `- YYYY-MM-DD: ...`, named for a card id; `README.md` and dotfiles skipped), orders the lines oldest date first, then by the first `#C<number>` in the line (lowest first), then by file name, and appends them after the last line of this file; `--write` also deletes the files. Nothing follows a symbolic link: a link, or a folder where a file belongs, is named and refused, as `changelog.mjs` does. The existing lines stay where they are. The fold is a card, not a commit the landing job makes: the Worker's self-deploy gate (`scripts/self-deploy-gate.mjs`, hash-pinned) wants a Checker PASS and a Security SECURE on every commit it would deploy, and the job cannot sign. So a fold card (a Board-Id starting `fold-data-fragments`) runs `--write` on a branch and is signed Quick like any card. `scripts/board-land.mjs` (the landing job; pinned, so it rides the next owner pack) reads the paths each tip changes against main (`git diff --name-only main...tip`) and REFUSES a tip that edits `docs/DATA.md` unless every card it carries is a fold card (a path that only looks like the file does not count; paths that could not be read make the tip wait); and it counts `docs/DATA.d/*.md` on origin/main (`README.md` not counted) and, at 5 or more (`FOLD_DUE`), logs `FOLD DUE: N DATA fragments wait ...` and writes `dataFragments` and `foldDue` in `land-report.json`, which Release and Manager read with the run's other lines. No migration, table or column; `scripts/board-release.mjs` is not changed. Tests: `tests/data-fragments.test.mjs` (two branches that each add a fragment merge with no conflict, and the fold writes both lines in date order) and `tests/landing-refuses-data-md-edit.test.mjs`.
