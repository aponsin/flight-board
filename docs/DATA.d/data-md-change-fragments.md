The same cure as `CHANGELOG.d/` (#C1019): `scripts/data-fragments.mjs` (`--check`, `--write`, or no flag to print the result) reads `docs/DATA.d/*.md` (each file one line, `- YYYY-MM-DD: ...`, named for a card id; `README.md` and dotfiles skipped), orders the lines oldest date first, then by the first `#C<number>` in the line (lowest first), then by file name, and appends them after the last line of this file; `--write` also deletes the files. Nothing follows a symbolic link: a link, or a folder where a file belongs, is named and refused, as `changelog.mjs` does. The existing lines stay where they are; a release or a pack runs `--write` once. No migration, table or column; no pinned file (`scripts/board-release.mjs` is not changed, so the fold is a command, not part of the landing job). Tests: `tests/data-fragments.test.mjs` (two branches that each add a fragment merge with no conflict, and the fold writes both lines in date order).
