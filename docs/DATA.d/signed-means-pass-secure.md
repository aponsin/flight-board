- 2026-11-17: "Signed" and "Security wanted" have one reading each (#C1163, `collector/signoff.mjs`). A review's note signs a commit only when its first line starts with the role's word, PASS for Checker and SECURE for Security (`isSignoff`); the probe's `signed` list used to count every note that did not start FINDINGS, while the landing job, the release tool, the re-cut tool and the self-deploy gate wanted PASS and SECURE, so a HOLD or STOP note read as signed on the board and landed nothing. A note that is neither a sign-off nor FINDINGS is now no sign-off and no finding. `scripts/sign-note.mjs` refuses a first line that starts with anything but the role's word, FINDINGS or STOP. A role with no word (another repository's reviewer) keeps the older rule (any note that is not FINDINGS). A card whose repo word is `flight-board` or `board` always wants Security (`securityAlways`; `wantsSecurity` is the one function the dispatch and the page's shown level read, and the probe adds `security` to such a card's reviews), because the landing job wants SECURE on every commit of the board's repository; a card with no repo word keeps the typed-level and reviewPaths rule.
