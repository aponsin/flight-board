- 2026-11-17: A group head lands only after the group check (#C1146, split out of #C1068). The landing job (`scripts/board-land.mjs`) wants two things on the exact head when it carries two or more cards (the Board-Id trailers of `main..head`): Checker's READ note in the new `refs/notes/group-check` (first line `READ`, then every file that two or more of the head's cards touch, one per line; `node scripts/group-check.mjs read --sha <head> --signer "Checker 2" --push` writes it, `files` lists them), and one run of the full suite on a snapshot of the head, which the job makes itself before the release tool's dry run and keeps per sha in `<stateDir>/<board>/group-check.json` (at most 20 shas, owner-only file). A merge commit lists no file of its own, so only the cards' own commits count, each by its Board-Id. Without the READ (or with a shared file it does not name) the head waits in the report's `waiting` and says which files; the suite is the snapshot's own `scripts/test-run.mjs` (as `npm test`), stdin closed, TMPDIR a temporary folder (HOME is the owner's: headless Chrome in a test fails under another), killed after `LAND_SUITE_SEC` in all (80% for the first run, the rest for the rerun); a red that names failing test files is rerun once on those files alone and counts green if they pass (the line says so); a red suite is a refusal for Release naming up to three failing tests; a green one is not run again. A head of one card, or none, asks for neither. The suite adds `LAND_SUITE_SEC` (180) to a head's per-tip budget (`worker/probe-jobs.mjs`, on the knobs lint's FIXED list). No migration, table or column. Ships as the owner's pack (the landing job's pinned copy, so its land step moves). Tests: `tests/group-check-before-land.test.mjs`.
