- 2026-11-16: The probe reads each role's Remote Control switch from the app's session file (#C1122, split from #C1111). A live try on one roster session (switch off, then on, the file read at 5, 30 and 60 s each way) showed the file's `remoteControlUserEnabled` follows the switch within 5 s both ways, while `steeredByRemoteClient` stays true after the switch is off (it is history) and `remoteControlUserEnabled` is null on a session whose switch was never touched. So `appSessions` keeps one new boolean, `rcOff`, true only when `remoteControlUserEnabled` is exactly `false` (null, absent or any other value is not off); no other Remote Control key of the file is read. An agent's reading in the state gets `rcOff: true` when its session reads off, and has no such key otherwise (the schema accepts `true` only). The Worker puts one line per such role in Manager's batch (`rcOffWakes`, board-rules.mjs; row `rc-off:<role>`): told once per spell, its row goes when the switch reads on again, so a later spell tells again. The Crew tile shows a "Remote Control off" chip for a role that reads off (a live reading only). Tests: `tests/remote-control-from-session-files.test.mjs`.
