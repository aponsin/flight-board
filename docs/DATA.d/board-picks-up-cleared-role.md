- 2026-11-16: The watchdog picks up a role that cleared itself (board-picks-up-cleared-role, #C870). `scripts/pickup-watch.mjs` gains `passActions(rows, state, watching)` (returns `{actions, state}`), `watchRoles(psText)` and the command `--pass <rows JSON or x> [--rows-file <file>] [--config <board.config.json>] [--state <file>]` (`--rows-file` reads the rows from a file; `--config` keeps only roster roles and prints `[]` with no readable roster; a role name is 2 to 24 characters) (exports `REARM_TEXT`); `decide()` and its one-role command are unchanged. A row is `{role, state, tokens, remoteControl}`, the session tools' readings only. The program keeps a history by role in the state file (default `~/.flight-board/pickup-pass.json`: `high` a reading of `LOW_START` (60 000) or more since the last pickup, `sent` its own pickup, `worked` the role seen working after it, `sawWatch` a watch seen armed, `rearmed`) and reads the armed watches from `ps -axo args` (a `wake-watch.mjs` line with `--role <name>`). The answer is a JSON list of `{role, do: "send_message", text}` or `{role, do: "set_remote_control", on: true}`. `/pickup <Role>` when the role was `high`, is idle and its Messages tokens are under `FRESH` (5000), once per clear; "arm your dispatch watch" once per pickup when `sent`, `worked`, idle again, `sawWatch` and no watch armed now; Remote Control on when it reads "off". A role name not of the ROLE form (letters and digits, single spaces inside) and an unreadable row are dropped; an unreadable state file is an empty history. A first run on a session already cleared sends nothing (no `high` reading yet). No Worker, store or migration change: the local agent watchdog task reads the rows with `list_sessions` and `get_usage`, runs the command and does what it prints (the prompt text is `docs/watchdog-pickup-pass.md`). Tests: `tests/pickup-pass.test.mjs`.
