- 2026-11-16: `npm test` names every failing test as the last lines of its run, and writes them to a file (#C1091). On 11-16 Checker 2's first full run on #C1075 v3 went red, the output was cut off, nobody knew which test failed, and the rerun was green (an unknown flake). `scripts/test-run.mjs` (the #C1059 wrapper) now starts node's test runner with two reporters: `spec` to stdout, as before, and `scripts/test-failures-reporter.mjs` into a file in the run's own root. The reporter writes one line per failing test as it fails, `FAILED <file>: <name> -- <first line of the error>` (a describe, and a test that failed only because a subtest did, are not listed; a test file that crashes before its tests run is listed by its file). When the run ends the wrapper copies the lines to `<TMPDIR>/last-suite-failures.txt` (or the path in `SUITE_FAILURES_FILE`; a green run removes the old copy) and prints, as the very last lines on stderr, `FAILED TESTS (n):`, the first 40 lines, `... and N more` and `(the whole list: <path>)`. The run's exit code is unchanged. No migration, table or column; no pinned file. Tests: `tests/suite-names-failures-last.test.mjs`.
