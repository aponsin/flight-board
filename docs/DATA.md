# Flight Board Data

The board's data contract: every data point the board shows, where it lives, who writes it, where the truth comes from, and how fresh it must be. Agreed by the owner on 2026-11-04 after a row-by-row review (55 rows; the row-by-row discussion is in the owner's review page and its backup, outside this repository). This file is the version to build from. A change to a row needs a decision line under "Changes" at the end.

## Principles

1. **One writer per fact.** Status is written by the probe (a script) from evidence; words (cards, asks, answers, queue order) are written by people and agents; nothing is typed that evidence can show.
2. **Three freshness classes.** *Live*: read by a script from git, GitHub, the deploy or the app, at most 1 minute old. *Instant*: a person or agent wrote it; shown within seconds. *Daily*: one row a day, by script.
3. **One store.** A Cloudflare Worker with D1 holds everything; the page, the probe, scripts and agents' tools read and write the same store. No model copies data (the Collector is deleted).
4. **Refuse early.** The Worker validates every write against the rules in the same call. No end-of-turn hooks.
5. **The board reflects, it does not control.** It cannot stop a commit; it records what happened out of order and demands the explanation.

## Where things live (after the refactor)

- **The store**: Cloudflare Worker + D1. Evidence (from the probe), cards, asks, threads, decisions, queue order, acks, the refusal log, usage rows.
- **Your browser**: values computed from the store at draw time (counts, ages, ETAs).
- **Truth comes from**: the live site (its `/version.json`), GitHub (branches, signed notes, main, CI runs, pull requests), the Claude app on the Studio (session list, transcripts), files the scripts leave on the Studio, people (what an agent typed or the owner clicked), and the board's own history.

## Freshness and wiring

- The probe runs on the Studio every 60 s (launchd), reads the truth sources and writes evidence to the store.
- The page fetches one JSON view of the store every 2–3 s while visible, with a version tag; unchanged answers cost bytes. Thread history loads on open.
- The probe asks the store every 20 s "anything for Manager?" and starts one Manager turn per batch. No Monitor, no re-arming, zero cost while quiet.
- Usage: the probe runs the usage script every 5 min (no model).

- **Ask types** (Worker-enforced): Decision (question, 2–4 options, one recommended, screenshots for look questions), Action (numbered steps, copy boxes, "what you should see"), Terminal (commands on the Studio), Session start (exact words to type), Later (Manager's to-do for the owner; an ETA is required; the probe moves it into Needs you at the ETA or when its precondition is met), Approval (merge/release, data from GitHub, Approve/Withdraw read by the ship script), Answer (carries the question; Ack), Thread (free text, no buttons). - **Card states** = phase + condition: Planning · Queued for <phase> behind #C (any phase) · Building · In review at <phase> · Rework · Signed · Shipping · Deploying · Live; overlays Gated, Blocked, Stalled, Paused, Dropped. - **Rework**: a commit on the tip after a sign-off drops the card to Rework automatically; Manager must attach a reason from a fixed list (bug found in test, review findings, design change, security finding, owner change); until then "Rework: reason missing" and other writes on the card are refused. Reasons stay in the card's history.
