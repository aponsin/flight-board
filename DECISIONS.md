# Decisions

## A ship in flight is a new optional key in the state, and the Worker is redeployed for it (#C679)
Chose: the probe reads a pushed ship candidate itself (the newest remote tip matching `collector.candidatePattern` that is not on main, under 6 hours old, whose CI run has not failed or been cancelled) and posts it as an optional top-level `ship { version, ci, at }` in the state; the page's "Safe to restart" badge is never green while it is there and says why ("Not now: Ship v1.200.6 waiting on CI"). The Worker's copy of the schema takes the key, so the pack that installs it runs the Worker's redeploy first (one command for the owner, a STOP if it did not take), before the probe's job moves.   Because: on 2026-11-04 the badge was green while Release's ship waited on CI, the owner restarted, and the ship died with manual recovery. The cards saw a ship only through an open card a running run's title names, which misses a candidate whose cards are closed or whose queued run's title does not match; a restart is unsafe from the push to the merge, whatever the cards say.   Rejected: carrying it as a made-up card record keyed by the version (it needs no Worker change, but it would leak into card counts, nudges and the gate's card rules, and a card id is a promise about the board's cards); and waiting for a ship run's title (a queued run has no ship title yet).   Note: the key is an allowlisted, fixed shape (a version, an enum, a time): no branch name or text of a run leaves the Studio. A candidate left on GitHub after a red run is not a ship: a failed or cancelled run, or six hours, ends it. A CI read the probe cannot make (gh back-off or the call limit) leaves the candidate in flight as "pushed, not on main": never a green badge it cannot justify.   Revisit if: Release stops using candidate branches (the pattern then matches nothing and the key is simply never sent).

## A missing owner or ETA is red on the page and a GAP line for the lead, never a refused write (#C619)
Chose: the page marks a card's row red for "no owner" or "no ETA" (the page's own gaps, derived ETA included); the probe lists every open card with no `who` or no `etaLive` (the declared fields only) in `board-truth.json`, and the lead's watch prints it; the gate does not refuse a card for "no owner".   Because: the owner asked for the cards missing timing or owners to be visible without anyone remembering to look; a card is written before it is handed to anyone, so refusing the write would stop the lead's work.   A card held on purpose is neither listed nor red: its status is one of `nudges.parked` (paused) or "parked", it is queued, or it waits on the owner (`waitingOn` is the owner's name, alone or before a colon; the page also counts an open ask tied to it), because no ETA can be given and a line starts a lead turn. Any other `waitingOn` text holds nothing: it is the lead's routine "next is" field (13 of 14 open cards had one), so counting it would switch the feature off (Checker).   Note: the probe sees only the card's declared fields, the page also its derived state. So the probe may list a card whose row is not red: one the page gives an ETA from the median phase times, one up next between phases, one in a known wait or worked by the live state (no owner). The line asks for the declared field, which the lead is to write anyway.   Revisit if: the GAP lines are mostly such cards (move the median phase times into the probe) or too many (list fewer).

## The session's role is an integrity check, not access control
Chose: the gate takes a session's role from its title in the app (the transcript's latest custom title), then `FLIGHT_BOARD_ROLE`, and refuses when they disagree.   Because: a mistaken "/pickup <Role>" once made one role write as another; the title is what the owner sees.   Rejected: the conversation's last "/pickup" because that is exactly what went wrong.   Note: any session can rename itself or change its environment, so this guards against mistakes only. Nothing security-relevant may depend on it.

## The gate fails open on its own errors, closed on its rules
Chose: a config it can't read or a call it can't parse lets the write through with a note; a rule hit refuses (exit 2).   Because: the gate is a process guard; a broken gate must not stop the team's work.   Revisit if: a rule ever protects something that matters more than the team's pace.

## Rules that need the board's state wait for the collector
Chose: ids, phase order, one item per role and phase, and done-only-when-closed are checked by the collector against the mirror it keeps, not by the gate.   Because: a mirror kept by hand brings back the "lead remembers" dependency this project removes.

## Thread numbers come from one counter the lead moves in a pinned batch
Chose: `threads/<thread id>` holds `{num, title}`; `meta/threadSeq` holds `{next}`; the lead allocates with `scripts/thread-ids.mjs`, which numbers threads by their first message's time and writes batches that set the numbers and move the counter together; each batch is sent with the counter pinned (`if_version`), so it is all or nothing and two allocations can't both pass. The gate lets only the lead write either, and checks a batch's numbers are distinct and run up to the counter's new `next` - 1. The owner's page writes only a title.   Because: the owner asked for short typeable ids in opening order; a counter with a pinned write is the one race-free way the board's database offers.   Rejected: the page numbering a thread when the owner opens it, because the owner's writes don't pass the gate; numbers worked out from the newest export, because two allocations between exports would collide.   The gate also needs the counter pinned once it exists, and remembers the highest `next` the board applied (in its own state, raised by a PostToolUse hook, `gate/after.mjs`, so a batch the board refused can be sent again), so a batch never goes back below it (Checker: an unpinned batch could reset the numbering to #T1).   Revisit if: sessions on more than one machine write the board (each gate remembers only its own).

## The plan's states: free-text waits gate until the lead clears them; due days end in UTC; ideas stay their own list
Chose: a `waitsOn` entry that names no node and no card (the seed's "owner's yes") keeps its node gated until the lead removes it or declares the node done; an objective's due day ends at 23:59:59 UTC; "ideas not in the plan" are the open `ideas` collection, not plan nodes; a leaf with no card counts the `M` median toward what is left; work going on wins over a gate (a node with an open card is in progress, even if it waits on something).   Because: free text can't be checked, and showing it met would hide the wait; the collector gets the clock passed in and reads no time zone; the board already has an ideas list the owner uses, and a second kind of idea would split it; a step with no card yet still has work in it.   Rejected: ignoring free-text waits (the plan would say "next" while it waits on a person); the owner's time zone (one more config field for a few hours' difference); a plan node kind "idea" (a schema change the gate would have to learn).   Revisit if: the at-risk chip is wrong around midnight, or the lead asks to link an idea to a plan node.

## Every thread is numbered from the start; the owner's own new threads by the lead's next run
Chose: the gate refuses a new waiting item, or an agent's message into a thread with no `{num, title}` on the board, unless the same batch numbers it (like cards); the backfill numbers waiting items too and names untitled threads; a thread the owner opens from the board (t-<time>) is numbered by the lead's next `thread-ids.mjs` run, because the page's own writes don't pass the gate.   Because: items showed without their #T (the owner, 2026-10-26), and a number added by hand was skipped for answers and actions.   Rejected: numbering in the page (two browsers could hand out the same number without the pinned counter the gate checks).   Revisit if: the page gets a safe way to move the counter.

## The card's phase is the repository's when the evidence is firm
Chose: the page shows the collector's derived phase (head, notes, main, deploy) over the one the steps imply; steps keep the timings, a disagreeing step phase shows on the evidence chip; steps win only when newer than the run and further on.   Because: after a crash the agents stopped logging, and live cards showed "Stalled, Security up next" though the repository knew better.   Rejected: steps only (they go stale when an agent forgets or crashes); evidence only (it is up to an hour old between runs, so a review signed a minute ago wouldn't show).   Revisit if: the collector runs on every sign-off, so its word is never older than the steps.

## Closed cards' steps move to one timings document per card
Chose: the lead's `scripts/steps-archive.mjs` sets `timings/<card id>` {steps} (the raw steps) in the same or an earlier batch than the deletes of exactly those steps; the page counts a closed card's steps from `steps` and its timings, each once by id, and ignores an open card's timings; only the lead may write `timings` or delete a step. The collector's export keeps its 7-day steps window.   Because: `steps` held 2,283 documents and grew forever; the page subscribed to all of them and a collector run's export stopped at step 1 about one run in six (Director, #C210). Raw steps, not a summary, so a late step merges in like any other (Checker) and nothing is computed twice.   Rejected: writing the timings onto the card (an update needs its version pinned, and export files carry none); a phase summary in the timings (a late step would need it recomputed under a pin); exporting only steps since the last run (the nudges and the gate's overlap check need every open card's open steps); letting any role write timings (a forged one could make a card look shipped: Security).   Revisit if: the open cards alone outgrow one export page (1,000 steps).

## Versions come from the repository and the live site, never from the card
Chose: retire `plannedVersion` (the gate refuses it); a card shows its derived version, else its queue place from signed cards by readyAt, else its phase; the header's "Live now" reads the live site's build tag (one GET by the collector each run, `collector.liveUrl`), with "deploying" while main names a newer version.   Because: hand-written versions went stale with every bundled or reordered ship (the owner, via the lead, #C211); main is not live until the deploy finishes.   Rejected: main's newest version as "Live now" (it says live during a deploy, or after a failed one); the page fetching the live site itself (a page on another origin can't read it, and it would expose the viewer).   Revisit if: a team has more than one live site to show.

## Shipping now comes from the ship run's own branch
Chose: the collector reads the run's candidate branch (`collector.candidatePattern`) and the branch@sha its last commits name; those cards are "Shipping now", the other signed cards "Queued (n)"; the refresh hook treats the branch appearing or going like a ship.   Because: two cards said one planned version while only one was in the run (#C211); the run itself is the evidence, and the board must show it within minutes.   Rejected: the ship script writing a ship record to the board (a script can't write it; a person relaying it is the drift we removed).   Revisit if: a team ships without a branch of its own per run.

## Page-only releases publish through a pinned hook, never an allow rule
Chose: a PreToolUse hook on Artifact (`gate/publish.mjs`, pinned with the gate) that says "allow" only for the lead's publish (action publish or none, no field but action, url and file_path) to exactly the config's artifactUrl, of a file that after realpath is a regular `board-<commit>.html` or `board-v<NNN>.html` in the config's own folder, byte for byte the page the pinned `build-page.mjs` builds from the current link's template (the signed commit a board release moves it to) with today's config. Everything else is silence, so the app asks as before; the hook never refuses.   Because: the owner picked B in #T1051 (page releases go out once signed) and approved the hook; an allow rule in settings can't be narrowed to one artifact (Security: it would let any agent publish or delete anything).   Rejected: an Artifact allow rule (too wide); building with the current link's own build-page.mjs (code a board release moves would decide what the hook allows).   Test plan for auto mode (does an allow from a hook skip the app's consent?): after the install, Manager republishes the page already live (the same board-<sha>.html, harmless) and notes whether a consent card came; the hook's reason line shows in the transcript either way. If the app still asks, the hook is harmless and we say so in #T1051.   Revisit if: the app gives a narrower permission rule for one artifact.

## Each card's version is predicted in code, from the queue and two marks the lead sets
Chose: the Collector predicts every signed card's version (`collector/expected.mjs`): the newest of live, main and the run on now, then the queue by readyAt; cards with one `batch` share a version at the earliest member's place; each version is a patch unless a card in it has `bump` "minor" or "major" (the largest wins); a card in review shows the version after the queue "at the earliest". The guard keeps each card's last queue prediction (`expected.json`) and raises a CONFLICT for a ship in another version, a batch in two, or a bump unlike its cards'. Only the lead may write `batch` and `bump`.   Because: the board said "Queued (2)" and the lead worked versions out by hand, which drifted when the order changed (the owner, #T1039; picks A and A in #T1043/#T1044).   Rejected: every card its own ship (batch B: the team does bundle); always a patch (bump B: features ship as minor by the team's rules); the run's version as the prediction it is checked against (it would always agree with itself).   Revisit if: Release ships out of READY order on purpose; then the queue order needs its own field.

## A review few cards need is skipped unless the card asks for it
Chose: the skip kind `unlessTrue: <field>`: the phase counts only on a card whose field is `true`.   Because: a new review phase (a designer's) with `whenFalse` would hold every existing card, which carries no such field, at that review.   Rejected: `whenFalse` with the field written on every card (the lead would have to backfill and never forget it).   Revisit if: most cards need the review; then `whenFalse` fits.

## The collector's code moves without the owner; what constrains an agent doesn't
Chose: the scheduled collector runs `~/.flight-board/current/collector/collect.mjs`; `current` is a symlink to a pinned copy, moved by `scripts/current.mjs` only to a commit on main with Security's `SECURE` git note, and only to a copy that is exactly that commit. The gate's hooks, the refresh hook, the fence and everything they import stay pinned by commit in the settings, changed only by the owner's install. The fence accepts the link only as a symlink to `<install root>/<40-hex>`; step 2 checks it runs step 1's code. Edit and Write on `~/.flight-board/**` are denied. What gates a collector change is Security's Full review of the commit (the note is a process, not an identity), and the docs say so.   Because: every collector change cost the owner a hand install (the owner via Director, #C223). Director's line: anything that constrains an agent is the owner's click; anything that only reads or displays is not.   Rejected: a sandbox on the collector's Bash (Security's option A): it needs the network (git fetch, gh, the live site) and writes the repository clone's refs, so the sandbox would allow most of what it should keep out, for a new owner click; the fence from the link too (a moved link would then move what bounds the run).   Revisit if: the collector stops needing the network, or a review is ever skipped for a link move.

## Choices in an ask's text need buttons
Chose: the gate refuses a waiting item of any kind but `decision` (with options) whose text, question or title holds two lettered or numbered marks (`A)`, `B)`; `1)`, `2)`) or "option A"; an update without the kind is checked against the mirror's.   Because: an answer listed A) and B) with only an Ack button, so the owner couldn't pick (the owner, #C227).   Rejected: reading every "A." or "first, second" (too many false refusals in plain prose).   Revisit if: real prose trips it often.

## The live check runs at most once a minute, as two queries
Changed (#C556, the owner's B on #T1348, replacing #T1037): a turn that ends under a minute after the last whole check isn't asked again. 62% of the lead's board calls were reads, many of them this check, and a burst of turns paid for one each. The cost, which the owner saw before choosing (Checker on #C556): a ping dropped during such a turn is seen only at the lead's next checked turn, which can be later than a minute if the lead goes idle. A check that came back cut short or half done is still asked again at once. Revisit if: an owner word is missed for more than a minute, or the board's database becomes readable from a hook (then no turn needs a check).
Before: the Stop gate asks the lead for its live check at the end of every turn, with no throttle: the owner's messages since the last check, and the waiting items the owner replied to since (the page stamps a top-level `respondedAt` beside each reply). Both must come back whole for the check to count.   Because: the owner's A in #T1037 was one live check every Manager turn, so as never to miss the owner's word; #C394's 5-minute throttle let a turn end unchecked a minute after a check, and Manager missed the owner's 18:03Z reply on v3.19 for ~10 min (#C406). A button with no note writes no message, and a query can't reach the nested `response.at`. Two queries are still one check: option A was about never missing the owner's word, not the number of queries (Manager's B).   Rejected: every reply also writing the owner's word as a thread message (Manager's A): one query, but a line in every thread for each button press, a look change for the owner, and the end of the "buttons write only the response" rule; a throttle of any length.   Revisit if: the board's database can query a nested field, or one query can read two collections.

## The board's live state comes from a pinned script through the owner's own Worker
Chose: `collector/state.mjs` on launchd, every minute, from the owner's pinned copy, POSTs an allowlisted state (ids, enums, numbers, times) to a Worker on the owner's own Cloudflare account; the page reads it through a read-only MCP tool on the owner's claude.ai connector. The Worker keeps hashes of each board's token and MCP path only, checks every POST against the schema, and answers only what the schema rebuilds. The probe has its own copy of the phase rule, kept equal to `collector/derive.mjs` by a test.   Because: the board went quiet whenever the Collector (a model run, hourly) did, and the owner saw "nothing moved for 20 minutes" while three versions shipped (#C417, #C420). A script needs no model; the page can't reach the Studio, so the state must sit somewhere both reach. Security's ruling on the data plan: session titles and transcript tails can hold customers' names, contacts and pasted secrets, so only a card id and a tool's class come out of a transcript; the code is pinned (condition A) so a board release can't widen what leaves; strict at both ends (B); secrets made by the owner's install, 0600 in a 0700 folder, never printed (C); one address, bare 404s, no CORS (D); the page escapes or drops every value (E); the connector URL only in the owner's claude.ai settings, rotated by one command (F). The phase rule is copied, not imported, because the probe is pinned and `derive.mjs` moves with the link (#C278).   Rejected: the page polling the Worker itself (a token in a shared page, and CORS); the agents writing their own activity to the board (what failed: a quiet agent writes nothing); riding another product's Worker (Security; the account is the owner's personal one, which other Workers share, so this Worker keeps its own name, config, KV namespace and secrets, no route on any zone and no shared binding, and spends the account's KV writes only on a change the page shows, a 15-min heartbeat, and a daily budget); importing `derive.mjs` (it would pin the collector's phase logic).   Residual (accepted by Security): an agent running as the same user can read the token and post a forged state; it is display only, and the schema caps what it can say. The ids in it (a card id: 1 to 5 lowercase words of 16 characters at most; a role: one word; a phase: one lowercase word) are cut to the board's real shapes, so a forged state can't carry a sentence of instructions into a Claude conversation that reads it. Not done (Security's optional 6): rate-limiting failed POSTs too: each would cost a KV write, the account's, so a stranger could spend them; a failed POST does no other work (one hash, no read).   Revisit if: the app gives a page a way to read the Studio's state directly, or the probe needs a field the schema doesn't have (a new data plan to Security first).

## A page release goes out on top of a waiting install pack
Chose: a board release built on a signed install pack S goes out before the owner installs S, when every change to what the owner's install pins on the line from the installed pin is signed and the release adds none of its own; the release tool finds S itself (the newest such commit, every commit on the line descending from the pin). The pinned code still waits for the owner's install; only the link's code (the collector, the page) goes live early, so every pack's rehearsal proves that code works with the old gate and config. The link never moves back from a signed release on `main` that has S.   Because: the pack pushes its commit as a fast-forward and the release tool refused anything over a pinned change, so a waiting pack held every page release: v3.19's held four for 564 min (Director, #C412). Security's ruling on plan A, with S derived, not named, so no agent-supplied flag or config value picks which signed commit counts.   Rejected: naming S by a flag or a config field (Security); the pack leaving `main` alone and a later signed merge of main and S (plan B: a new merge to sign each time main moves).   Revisit if: a pack's link-run code can't be made to work with the old gate, which would need the old blocking again.

## The live state is the page's source of stage
Chose: while the live state's reading is under 3 min old, every place the page shows stage (phase lights, the running sub-step, Waiting on, the ETA, needs-you counts, the agent tiles) reads it first, and the Collector gives its cards the live phase too; the db (the Collector's derived/all and the steps) is the fallback, never the authority. The "Right now" panel goes; the header stamp alone says which source the board reads ("live · 40 s" or "from 14:02").   Because: the Director with the owner (board-state-probe's follow-up): the dashboard as it is should read the live state, rather than a second panel saying something different from the cards under it. The live state comes every minute from a script; the Collector is an hourly model run.   Rejected: keeping both (two answers to one question); dropping the Collector's reading of the repository (it alone gives times, waits, versions and the READY dispatch, and it is the fallback).   Revisit if: the live state gains what only the Collector gives today, so the Collector can stop reading the repository.

## Steward's pickup watch trusts an idle reading, without a transcript check
Chose: Steward's pickup watch (#C498) sends `/pickup <Role>` once the target is idle and its context reads under 5,000 tokens, with no check that the clear really happened. A failed clear is left to the hourly keeper.   Because: the context reading is unavailable for an idle session and counts as 0, so the test passes for any idle session, cleared or not (Steward, in the rehearsal). The only check that tells them apart, the target's message count from `list_events`, needs an allow rule that lets Steward read any session's transcript. That is a wider permission than the risk is worth: the cue sends the watch and calls `clear_session` in the same turn, so a failed clear is rare, and the hourly keeper still picks the session up (Manager, #C502).   Rejected: requiring the target's `lastActivityAt` to be after the watch message (the cue's turn ends after the send whether or not the clear worked, so it always passes); the `list_events` count (the permission above).   Revisit if: a session gives a context or message-count reading that works while it is idle, or a pickup ever lands on a session that never cleared.

## The cards' truth comes from code that reads the repository, not from someone remembering to write it
Chose: the every-minute probe reads GitHub's run titles ("vX: <branch>@<sha>", running) and marks the card whose tip they name `shipping`; the page then says "Shipping now", "Signed, waiting for Release" (every sign-off its level needs is on the tip, not on main, no run on it) or "Waiting for <role>" (a reviewer missing) from the live state alone. The probe also writes board-truth.json, and the lead's wake watch prints `SHIP <card>` once per tip (tell Release to ship it) and `CLOSE <card>` once per tip (its commits are live while the card is open); a card waiting on its done test (a checkAt) is not asked to close. The gate refuses a live step unless the same batch sets that card's status to done.   Because: on 2026-11-02 the board looked stuck three ways, each from a write nobody made: no card showed shipping while four versions shipped, a fully signed stack sat with nobody telling Release, and 16 cards stayed open for hours after their pack was installed. A script reading the repository can't forget.   Rejected: the probe writing the card's status itself (it has no write access to the board database by design: it posts an allowlisted state, ids, enums, numbers and times, to the Worker, and a probe that could write cards would be one forged state from rewriting the board); the page closing cards when it is open (an unattended write outside the gate).   Not done: waking Release directly. The probe can't message a session; the line reaches it through the lead's watch as WAKE, ASK and CONTEXT RESET lines do.   Revisit if: the probe gets a write path with its own gate rules, or a session can be woken from a script.

## The restart pill counts any agent's command in the last 15 seconds
Chose: the board's "Safe to restart" pill (#C613) turns red, "Not now: <Role> is running a command", while any agent but the lead has a Bash call under 15 seconds old in the live state, in any phase. On top of that, as first built: a ship running, Release on a command within 45 seconds ("is publishing"), and another agent on a command within 45 seconds while its card is in the ship phase ("is pushing or installing"). With no fresh live reading there is no pill. The pill's tooltip says it is an estimate from each agent's last tool call, not from the command.   Because: the live state carries the tool's class and when it was used, never the command, so a push or an install can't be told from any other shell command; and the first build counted only the ship phase, so Builder, Boardsmith and Checker pushing from the build, test and checker phases all read as safe (Checker's finding on 787b376).   Rejected: any command within 45 seconds in every phase (red whenever anyone works, so the owner would learn to ignore it); keeping only the ship phase and rewording the promise to "a ship or Release publishing" (it would say safe during a push).   Not done: a running scheduled task is not in the live state; it is its own card (a new probe field, so a pinned-file change with a pack).   Revisit if: the live state can name what a command is (a data plan to Security first), or the pill stays red more often than it is useful.

## The old board page's fonts are self-hosted, from @fontsource
Chose: six latin woff2 files in `page/fonts/` (Barlow Condensed 600 and 700, Source Sans 3 400 and 600, JetBrains Mono 400 and 600), each family's OFL text beside them, taken once with `npm pack` from registry.npmjs.org: `@fontsource/barlow-condensed@5.3.0`, `@fontsource/source-sans-3@5.3.1`, `@fontsource/jetbrains-mono@5.3.0` (2026-11-09, #C723). No package is a dependency. The store build writes `@font-face` rules on the Worker's `/fonts/`; the artifact build keeps Google's links.   Because: served by the store Worker, the page's policy loads fonts from the Worker only (parity plan rule 3), and the old look needs these three families. The owner said yes to the download on #T1668 ("yes downlowd it", 21:11Z, relayed by Manager).   Rejected: the Mac's installed Nerd Font copies (patched, not the same glyphs); Google's servers (the policy would have to name them).   Revisit if: the page uses another weight or script (latin-ext), or a font's licence changes.

## The store Worker serves the old board page as static assets, at /board
Chose: `scripts/build-store-page.mjs <board.config.json>` builds the artifact page (fixtures checked), swaps its Google font links for `@font-face` rules and wraps it in a document, into `dist/store-page/` (git-ignored), which `worker/wrangler.board.toml` deploys as `[assets]` with `run_worker_first`. `GET /board` serves it after the Access check, with a fresh nonce on its script per response: `default-src 'none'`, script by nonce only, fonts, images and connections from the Worker only, no framing. The small page stays at `/` until the owner switches (#C723).   Because: the page carries the team's config, so it can't be committed or generated into a module the tests import; assets keep it out of the code and the repository, and the Worker still decides who sees it. `/board` lets old and new be compared side by side on one address.   Rejected: a generated module and a second entry file (Boardsmith's first cut; a deploy must pick the right entry, and a fresh checkout's tests can't import it); serving the asset directly (no identity check of ours).   Revisit if: the owner switches (the old page moves to `/`), or the assets binding can't run Worker first on the plan the account has.

## A card with no branch is read from the exact Board-Id trailer on main, last 400 commits
Chose: when a card has no branch tip, the probe takes the newest of the last 400 commits on the repository's main line whose body has a whole line `Board-Id: <the card's id>` (the id goes to git as a fixed string; the line, the 40-hex sha and the exact id are checked again in code). A card that still has a branch tip is read from the tip only (2026-11-10, #C725).   Because: a team-repository card whose branch was merged and deleted (c722, c724) had no head in the store, so the board showed it stalled or queued although it was signed and live.   Rejected: a prefix or regex match (another card's id that starts the same would match); reading the Collector's old output (the store does not carry it).   Known and accepted (Security, low): a merged outside commit, such as a pull request's own commits when merged rather than squashed, could carry `Board-Id: <our card>`. That changes only what the probe reports for a card with no branch tip (its phase and display); it is not a sign-off, since signatures are checked by exact sha.   Revisit if: such a commit appears, or cards outlive 400 commits on main.
